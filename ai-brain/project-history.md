# Project History

Chronological log of major decisions, in roughly the order they happened. Skim for context on *why* something is the way it is before assuming it's wrong.

1. **Mobile pass on the original design.** Header made `fixed` (was `sticky`) with a spacer div to compensate; hamburger menu added for mobile nav (states/login/signup collapse into it); VIN plate made responsive (icon-only copy button, `overflow-x-auto` safety net); spec grid repeatedly fought over 1-vs-2 columns on mobile (see `rules.md` — this one kept regressing).
2. **Removed the "State Preview" QA switcher entirely**, per explicit request — it let reviewers jump between synthetic edge-case states (loading shimmer, invalid VIN, returning user, rich/sparse/negative-flag data) via a dropdown in the header. Replaced later by real sample-data switching (#4).
3. **`agentation` package integrated** as the visual-feedback tool driving most of this project's review cycle — gated behind `import.meta.env.DEV`, mounted in both render branches of `App.tsx`. This is what produces the "Page Feedback" formatted messages this whole history is a response to.
4. **Replaced the fake mock vehicles (Subaru Forester / Honda Civic / Ford Mustang) with two real decode datasets**, supplied as actual API response JSON:
   - `FORD_FUSION_SAMPLE` — 2017 Ford Fusion SE, VIN `3FA6P0HD8HR352953`. Has a real sales-history record *and* a bid.cars auction listing photo — `statusType: 'rich'`, clean.
   - `JEEP_CHEROKEE_SAMPLE` — 2019 Jeep Cherokee, VIN `1C4RJEAG2KC823978`. Originally also had auction data, but was **later deliberately stripped of `auctionListing`/`auctionDetails`** on request, specifically so there'd be a demonstrable "no auction record" scenario — falls back to its 18-exterior + 9-interior photo gallery slider and shows a factory color-swatch row instead. `statusType: 'negative_flag'` (branded/collision) is kept regardless, since that reflects DMV/title records independent of whether an auction photo exists.
5. **Full color rebrand, twice.** First pass: primary green (`#0E5748`/`#147A63`/`#E3F2EC`) → navy (`#013479`/`#024EB6`/`#E3ECF9`), accent amber (`#F5A524`) → rust-orange (`#BE5103`), done via scripted find-and-replace (see `playbook.md`). Then **immediately superseded**: accent changed again from rust-orange to gold (`#F9AD24`) per a follow-up request specifying exact hex values for "Primary" and "Secondary/Accent." A later round also caught and unified remaining green (`#1E8E5A`, the "success" semantic color) to navy, except star-rating icons which use gold instead (ratings convention).
6. **Site-wide font-size floor of 14px.** Every `text-xs` and arbitrary sub-14px size bumped to `text-sm`, again via scripted replace. Uncovered real layout bugs as a side effect — several 2-column mobile grids with `whitespace-nowrap` labels started overflowing once the text got bigger (fixed by switching those grids to single-column on mobile).
7. **Press-state interaction simplified.** All `active:scale-95` / `active:scale-[0.99]` replaced with `active:opacity-90` across every CTA button.
8. **Auction/sales-history image system built out** in `GarageCard.tsx`: priority chain (auction listing photo → sales-history photo → exterior/interior slider → plain photo → placeholder), an auction-detail stat row (Auction Date/Location/Odometer/Primary Damage) that only shows alongside the auction alert box, a "What we check for?" popup checklist, a Carfax-vs-us comparison popup, and — most recently — a factory color-swatch row that appears *instead of* the auction box when there's no auction record. The swatch row was originally a large boxed section above the image/specs grid; shrunk to a single compact row and moved below the grid per feedback.
9. **Removed the logged-in state entirely from this page.** The header's user-badge/logout/garage-shortcut UI, `App.tsx`'s `isLoggedIn`/`userEmail`/`savedVehicles`/`currentView` state, and the `MyGarageView` routing were all removed — this preview page has no authenticated view of its own; that's the separate Garage app's job (see `rules.md`). Replaced the old "click Garage to see saved vehicles" flow with the direct sample-vehicle switcher in the header (#4), since that's what people actually wanted: a way to flip between preview versions, not a login flow.
10. **Preview-sample switcher UI iterated**: started as a segmented tab control, changed to a native `<select>` dropdown per feedback, then had an info icon added to clarify it's a reviewer tool (not part of the real design) — the icon initially used the `title` HTML attribute for a tooltip, which didn't reliably show up under the automated review tooling, so it was replaced with an actual CSS `group-hover` tooltip (a real DOM element, not a native browser tooltip) for reliability.
